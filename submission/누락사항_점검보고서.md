## 1. Git 및 분석 기준
- 저장소: https://github.com/yejun5380/DeliveryApp / 현재 브랜치 `master`.
- 로컬 master: `636522eb4cdc5d0e01ac44d7e4702febd16639a8`. fetch 후 origin/master: `4acace6f0a39f06b05fc0a298211e2f616460c6a`.
- `git fetch origin` 성공. 로컬 전용 커밋 0개, 원격 전용 커밋 1개 (`4acace6 Update README.md`).
- 로컬·원격 차이는 `README.md` 한 파일뿐이다. app.py·templates·DB·presentation의 차이는 없다.
- 개발 기능 분석은 현재 작업 트리 소스(원격과 동일), 주차·향후 계획은 최신 원격 README를 사용했다. 원격 README는 `git show`로 읽었고 작업 트리 README는 바꾸지 않았다.
- 작업 시작 시 미추적 `submission/.work/`만 존재했고, 추적 개발 파일의 미커밋 변경은 없었다. 기존 .work 내용은 보존하며 분석·제작 도구를 갱신했다.
- pull/reset/checkout/merge/commit/push는 실행하지 않았다. `.env`는 읽거나 출력하지 않았고, SQL은 파일로 읽었을 뿐 실행하지 않았다.
- 운영 MySQL에 접속하지 않았으므로 현재 운영 스키마와 데이터, FK 적용 여부는 확인하지 못했다.
